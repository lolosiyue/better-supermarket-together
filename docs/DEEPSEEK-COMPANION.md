## 開始使用

1. 關閉遊戲，把安裝包內的 `BepInEx` 合併到遊戲目錄。保留原有設定檔。
2. 讀取商店，按 **F7** 開啟同伴面板；亦可由 **F10 → F7：DeepSeek 同伴** 開啟。
3. 填寫員工編號，按「綁定員工」。也可以在 **F10 → 員工改名** 的對應員工旁按「同伴」。不會新增員工，也不會自動更改名字。
4. 面板底部填入 DeepSeek API 金鑰並按「儲存 API 設定」。預設網址 `https://api.deepseek.com`、模型 `deepseek-flash`。金鑰欄留空會沿用既有值。
5. 輸入訊息，按「傳送」。按「取消請求」可停止待處理回覆。開啟面板時會暫停自己的移動／視角控制，關閉後恢復；遊戲世界仍會運行。

範例：

- 「你好，我叫阿明，記住我喜歡你用廣東話回答。」
- 「幫我去補貨。」
- 「改去收銀。」
- 「去倉庫把貨放好。」
- 「你先休息一下。」
- 「你記得我的名字嗎？」

## 派工能力

可變更綁定員工的職務：休息、收銀、補貨、入倉、保安／拾回掉落商品、維修、網購包裝、生產。亦可使用一般商品／貨架補貨目標、跟隨房主及最多六步的順序計畫；具體搬運、動畫及庫存仍由原遊戲執行。網購包裝不等於採購。

目前不支援指定生產成品／客製配方貨架或工作站、不支援獨立清潔、自由搬物、條件排程或以聊天購買商品。每回合最多接受一個變更計畫／模式的動作；未通過工具參數檢查時不執行整組指令。

搬運中的箱子、已取得的生產原料及未完成的網購包裝，不會為了改職務而被丟棄；計畫會等待安全交接。派工走房主的原生伺服器處理函式，並檢查實際職務是否變更。計畫接受及後續完成／失敗事件會寫入對話，即使 API 結果回覆失敗仍能看到。

員工被解僱時會解除綁定；切換商店、失去房主身分、解除綁定、重綁或取消請求，都會使舊回覆失效。重新讀檔時比對員工編號、角色資料及名字，不會在比對失敗時隨意控制同一位置的新員工。身份有歧義時需手動重新綁定。

## 記憶與金鑰

- 每個商店按原生 `CurrentFilename` 雜湊成獨立檔名，存於 `BepInEx/config/BetterSupermarketTogether.Companion/<hash>.json`。
- 保留最近 40 則對話／執行記錄，每則最多 2,000 字；長期偏好最多 24 項、每項 200 字。採用暫存檔替換並保留上一版 `.bak`。
- 自然語言「記住……」由 `remember` 工具寫入。可要求忘記面板中某一項編號；這只刪除該項偏好，原始對話仍存在。
- 「清除對話與記憶」按兩次會清除本商店近期對話、偏好及前一版備份，保留綁定。無法讀取的損壞記憶檔會保留，不會自動覆寫。
- API 金鑰存於本機 `BepInEx/config/BetterSupermarketTogether.deepseek.key`（純文字），不放入聊天、一般設定檔、安裝包或日誌。亦可在啟動遊戲前設定環境變數 `DEEPSEEK_API_KEY`；本機金鑰檔優先。
- 聊天會把本次訊息、近期對話、偏好和遊戲狀態摘要送往所設定的 API。遊戲狀態包括日期、時間、開店狀態、綁定員工職務／狀態、攜帶數量、罷工及生產摘要。
- API 為背景 HTTP 請求，單次 45 秒、整輪 50 秒逾時；不在主執行緒同步等待。沒有填金鑰時，仍可先綁定員工及載入外觀。

API 金鑰請直接填入遊戲面板，不用貼到聊天。3D 資產免費下載；API 服務用量按所選服務商條款計算。支援相容 API 基底網址（例如本機 `http://127.0.0.1:1234/v1`）；遠端網址只接受 HTTPS，禁止網址內嵌金鑰。相容服務需接受聊天工具及非思考模式欄位。

## DeepSeek 娘外觀

隨附 [tegnike/deepseek-chan-vrm](https://github.com/tegnike/deepseek-chan-vrm) 的 VRM 1.0 模型，原角色上善无形、女僕設計 ZipZipPipe、3D 模型 ニケ。模型獨立使用 **CC BY-NC-SA 4.0**；需署名、非商業用途，修改後公開需按相同授權分享。完整原始條款、署名與固定版本雜湊位於 `BepInEx/plugins/BetterSupermarketTogether/Companion/`，不由程式碼的 MIT 授權替代。

模型僅在房主本機顯示，其他玩家仍看到原生員工。使用原有員工碰撞、尋路、道具、名字及網路狀態。載入器只接受隨附固定 SHA-256 的模型；支援基礎貼圖、蒙皮，以及原生骨骼動作同步，動畫改善測試版另加入裙擺／尾巴／頭髮骨鏈慣性及身體碰撞約束；尚未實作 MToon、口型或表情。

原生員工可使用 Generic Bip01 或可辨識的 Humanoid 骨架，不再要求 `Animator.isHuman`。按原生蒙皮網格的 bind poses 校正骨軸、身高及腳底位置；原生動畫和手部 IK 繼續運行，外觀在 LateUpdate 接收姿勢。不同身材的手持物對位仍需實機觀察。沒有足夠骨骼配對時保留原有外觀並回報日誌；模型／骨架未就緒會每 1–5 秒重試，完整載入失敗會等待至少 30 秒，無需重新綁定。來源角色被替換或解除綁定時會還原原有外觀及動畫剔除設定。

可在設定檔 `[Companion]` 將 `UseDeepSeekAvatar = false` 關閉外觀；聊天及派工仍可使用。源碼包不含大型 VRM，重建完整安裝包前執行 `download-model.ps1`，會下載固定版本並核對雜湊。

## 動畫改善測試版（2026-11-02，基於 1.4.1）

- 走路保留原生節奏，增加兩段式腿部 IK，將步伐對齊原生腳部位置並保留 VRM bind pose 的腳部偏移；限制可達距離，不拉長骨骼。

- 使用隨附模型的 40 組骨鏈、127 段有效骨骼及 sphere/capsule 碰撞資料，包含八組裙擺與鯨魚尾巴。阻尼、重力、硬度採用模型資料，裙擺較硬、尾巴較柔軟；碰撞修正可超過預設擺角以避開身體。
- 動態在原生姿勢及手腳 IK 後更新，以世界座標保留移動慣性；不宣稱完整 VRMC_springBone 相容（未採用 center 鎖定）。長幀、瞬移及大角度瞬轉會重設動態，避免骨鏈暴衝。沒有環境／地板布料碰撞。
- Release 編譯通過（1 項既有 WarehouseOptimizer 未賦值警告）；214 項自動檢查通過，包括 7 項新增 IK 檢查與 1,000 組目標的骨長／有限值驗證。模型骨鏈拓樸、碰撞參照及不覆蓋人形骨骼的靜態檢查通過。
- 尚未實機驗證走路、裙擺穿模、手掌／托盤接觸、尾巴觀感及效能；數學測試不等於 Unity 執行測試。不同手掌尺寸與不可達手位仍可能留有誤差。
