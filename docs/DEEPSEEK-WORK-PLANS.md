# DeepSeek 自主工作與順序任務（1.4.0）

1.4.1 已統一此功能的介面文字，改以獨立狀態及訊息鍵處理完成／失敗；見 [文字翻譯說明](COMPANION-LOCALIZATION.md)。下方 1.4.0 API 合成測試為歷史驗證。

綁定一名員工及設定 API 後，同伴可依商店狀態自主選擇工作，也能接受指定商品／貨架補貨、跟隨房主及最多六步的順序計畫。沿用原生員工、箱子、庫存、尋路和骨骼動畫。

## 操作

按 **F7**：

- **自主工作：開／關**：開啟後先等待手上工作安全交接，再開始自主評估。關閉會停止新的自主決策；已接受的有限計畫仍可完成。
- **停止計畫**：取消待處理 API、關閉自主模式，停止後續步驟；先處理手上的箱子、原料或訂單，再休息。
- **指向貨架**：先把視角準星對準一般商品貨架，開 F7 後按此按鈕，取得本次商店的 `S1`、`S2` 等編號。可說「補滿這個貨架」。
- 右側 **工作計畫** 及 **本商店的記憶** 可捲動。下方保留 cache／token 用量。

開啟面板時世界仍運行；關閉面板後工作和自主評估繼續。自主模式預設關閉，每次讀檔／進商店後需重新開啟；計畫和貨架編號只存在本次房間，不會在下次讀檔後重播。

## 可以直接說

- 「之後由你根據商店狀態自主安排工作。」
- 「停止自主安排。」
- 「把這個貨架補滿，再持續去收銀。」
- 「補滿 S4 貨架的原味牛奶，再去收銀。」
- 「完成一輪維修，再去收銀。」
- 「先收銀兩分鐘，再去入倉。」
- 「跟著我，直到我給你其他工作。」
- 「跟著我三十秒，再補滿這個貨架。」
- 「取消整個工作計畫。」

商品名稱有歧義時，模型會被要求先詢問。它可用 `inspect_shop` 按名稱、商品 ID 或貨架 ID 查詢，每頁最多 20 列。完整商品目錄不會每次全部塞進提示；狀態摘要提供目前較缺貨的列、準星選中貨架、倉庫可用件數、結帳顧客／空閒收銀台、地上箱子、待修設備和訂單數。

## 完成條件

| 步驟 | 如何完成 |
| --- | --- |
| 指定商品／貨架補貨 | 擷取開始時各列的缺口；同伴實際放上該列的數量累計達到缺口，或該列已補滿，即達成目標。顧客持續取貨不會讓既有進度倒退。 |
| 原生職務「完成一輪」 | 觀察原生經驗值的已確認進度，再等待安全交接。收銀會等待交易完成；生產的一輪指員工原料交付／原生員工任務，不保證成品機器已生產完。休息需用限時或持續模式。 |
| 限時工作／跟隨 | 5–1,800 秒的遊戲運行時間；暫停遊戲時不累計。到時仍會等待安全交接。 |
| 持續工作／跟隨 | 持續至玩家更改或停止，只能放在計畫最後一步。 |

前一步達標且手上物品處理完，才會開始下一步。有限計畫最後一步完成後休息；不會把指定補貨自動變成全店補貨。失敗會清除後續步驟，例如缺貨、貨架移除／商品標籤改變、路徑長時間停滯，均不會直接跳到 B。

補貨只從既有一般倉庫箱取貨，限一般零售商品貨架；可同時限制商品 ID 和貨架 ID，亦可省略其中一個。它不會購買商品、改標籤或移動貨架。本版未提供生產成品／客製配方貨架的指定補貨。

貨架 ID 對應物件身分，不依賴會隨家具移動而改變的排列索引。刪除同名／同位置貨架再放一個新的，也不會被當成原目標。

## 自主評估與用量

預設每 **120 秒**至多開始一次自主決策，每個滾動小時最多 **20 次**。只有商店狀態改變或計畫結束、員工可安全接手、沒有進行中的計畫／聊天請求時才評估。狀態不變時不反覆詢問；也不為暖快取增加請求。

設定檔 `[Companion]`：

| 設定 | 預設 | 可設定範圍 |
| --- | ---: | ---: |
| `AutonomyIntervalSeconds` | 120 | 60–1,800 |
| `AutonomyDecisionsPerHour` | 20 | 1–60 |

一次決策可能先查詢，再提出計畫，最後回覆，最多四次 API 回覆；預設自主模式的上限為每小時 20 次決策／至多 80 次 API 回覆，另計玩家自行聊天。API 服務依供應商規則收費；F7 的回覆數和 token 數會把每次實際回覆分開記錄。

API 失敗後，重試間隔為 120、240、480 秒，之後上限 900 秒，仍受每小時額度限制。玩家新訊息可取消尚未回來的自主回覆，舊回覆不能稍後覆蓋新指令。玩家明確安排的工作計畫執行期間，自主模式不會插隊。

自主決策只允許查詢商店、有限工作及有限補貨計畫。程式端拒絕自主跟隨、永久工作、修改記憶、改變自主開關或取消玩家計畫。跟隨只跟隨房主，沿 NavMesh 行走、保持約數公尺距離；無法到達或停滯會報錯，不會傳送角色。

## 執行與驗證

DeepSeek 提出結構化工具要求，模組先驗證整組參數。每回合最多八個通過驗證的工具要求、一個變更計畫／模式的動作，最多三輪工具交換及一輪結果回覆。可修正一次格式錯誤；錯誤批次不執行任何工具。固定工具 schema／`tool_choice=auto` 沿用 [前綴快取設計](DEEPSEEK-CACHE.md)。

接受計畫只表示排入佇列。開始、進度及完成由本機控制器和原生遊戲狀態決定，模型回覆本身不能確認成功。停止、替換計畫及失敗時，會等待箱子／原料／已承接訂單處理完；不以丟棄物品強制交接。若從原生員工介面改職務，會取消同伴待處理回覆、計畫及自主模式，由原生介面接手。

指定補貨會同時限制取任務及剩貨轉架；即使關閉全域「聰明補貨」，此名綁定員工仍保留所需的目標、占用和路徑檢查。其他員工繼續使用原有機制。
