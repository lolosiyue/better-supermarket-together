# DeepSeek 娘指揮其他員工（1.4.3）

F7 綁定同伴後，可以要求她安排其他已僱用員工的職務。員工編號與原有員工介面相同，從 1 開始。

範例：

- 「列出現在員工各自在做甚麼。」
- 「安排 3 號去收銀、5 號去補貨、7 號去入倉。」
- 「讓阿明去維修。」（同名時應先確認員工編號。）
- 「取消剛才還未執行的員工派工。」
- 「讓 3 號休息。」

預設是臨時派工：完成一輪有實際進度的工作後，等到手上物品安全交接，再恢復接令前的職責。可指定工作時長；只有明確要求長期／永久調職時才保持新職責。臨時休息預設兩分鐘。

可派職務：休息、收銀、補貨、入倉、保安／拾回掉落商品、維修、網購包裝及生產。只可指揮已僱用員工，不能控制顧客。對其他員工的指令目前是原生職務分配，不含指定商品／貨架、順序計畫或跟隨；這些仍只適用於同伴本人。既有自主模式保持只控制同伴本人，其他員工由玩家聊天明確派工。

## 執行及回報

名單查詢每頁 20 人，一次派工可包含最多 64 名不同員工。模型使用名單的本次會話 ID；此 ID 綁定實際員工物件與欄位，不以姓名或可重用的編號直接執行。全批先檢查有效性；若包含失效對象則不排入任何一項。

每名員工獨立等候安全交接；手持物、已開始的網購包裝、生產與其他受保護工作不會被強行中止。排入不等於職務已改，更不等於完成工作。實際呼叫遊戲的職務切換後核對職務及 priorityArray，再在聊天顯示成功／失敗。臨時任務及待交接數顯示在 F7 工作狀態，最近 16 項派工結果會進入後續模型狀態。

待派工於 180 秒遊戲時間後逾期；完成一輪模式若十五分鐘沒有確認進度，會在安全交接後回原職，不會聲稱完成。指定時長支援 5–1800 秒。玩家手動改職務會取消該員工的自動復職，保留玩家新設定。員工離職／替換不會把舊指令套給新人。

F7 停止計畫／取消員工派工會清除未開始的指令，已開始的臨時工作則安全復職。停用插件、解除綁定及重綁也會安排其他仍有效員工的安全復職；明確長期調職不會被復原。新綁定的同伴身份以玩家操作為準。

臨時任務追蹤目前限本次房間會話，不跨讀檔恢復；離開商店前應先取消並等候復職。直接在臨時職務期間存檔／離開，原生遊戲可能保存當時職務，下一次讀檔需自行確認。

## 安裝與回退

關閉遊戲，備份目前的 BetterSupermarketTogether.dll，再將安裝包的 BepInEx 資料夾合併到遊戲目錄。保留既有設定、API 金鑰及聊天記憶；不需新增設定。回退時恢復備份 DLL。本次沒有自動覆蓋遊戲中的插件。

## 驗證與限制

Release 編譯成功，保留既有 WarehouseOptimizer 未賦值警告。275 項自動檢查通過，包括批次結構、重複／失效對象、派工權限、忙碌交接、外部變更優先、逾期、取消、回報及本地化持久化。另以獨立測試輸出副本注入無效 fixture，確認錯誤被捕捉並以 exit code 1 結束，不再是未處理例外。

未呼叫真實 DeepSeek API，未執行遊戲內派工、多人同步或動作視覺驗收，未更改商店存檔。模型能否穩定理解每種自然語句，以及動畫穿模／托盤對位與效能，仍需實機觀察。
